fix evaporation command

Syntax:

fix ID evaporation nevery mix-ID keyword values ...
  • ID is documented in fix command
  • evaporation = style name of this fix command
  • nevery = perform update every this many timesteps
  • mix-ID = mixture ID to which evaporation is applied
  • keyword/value pairs: 
      mass value                = initial particle mass seed (kg)
  radius value              = initial particle radius seed (m)
  temp value                = initial particle temperature seed (K)
  heatflux/constant value   = uniform heat flux (W/m^2)
  heatflux/file filename    = HDF5 heat-flux map

Examples:

fix fevap evaporation 1 Droplet mass 2.796e-10 radius 5.0e-5 temp 773.15 heatflux/constant 5.0e6
fix fevap evaporation 1 Droplet mass 2.796e-10 radius 5.0e-5 temp 773.15 heatflux/file heatflux.h5

Model solved (current implementation):

dr_d/dt = -(A_M/rho_L) G_evap
dT_d/dt = [3/(rho_L C_p r_d)] [Q_s - G_evap (DeltaH_vap/N_A)]

Q_s is either constant or interpolated from heatflux.h5. The evaporation update is applied as symmetric half-steps: START_OF_STEP (dt/2) and END_OF_STEP (dt/2), so one full dt per active step where ntimestep % nevery == 0.

Droplets are removed after 90% mass loss (mass <= 0.1 * reference mass).

For compatibility with movers that use species mass, this fix also synchronizes species[ispecies].mass to the updated droplet mass when the new mass is positive/finite.

Expected HDF5 layout for heatflux/file:

  • Coordinates (choose one): 
    1) grid/Rc (nr,), grid/Zc (nz,)
2) grid/R (nz,nr), grid/Z (nz,nr)
3) R (nz,nr), Z (nz,nr)
  • Field dataset: 
    fields/q_mag (nz,nr)   or   q_mag (nz,nr)
  • Reader validation: 
    nr>=2, nz>=2
q_mag shape must match (nz,nr)
axes monotonic increasing
non-finite/negative q_mag are clamped to 0
  • If primary interpolation yields zero, implementation also tries a transposed q_mag index path for robustness with ambiguous file layouts.

Expected HDF5 layout for plasma fields (used elsewhere):

r (nr,), z (nz,)
required 2D fields (nz,nr):
dens_e, temp_e, dens_i, temp_i,
parr_flow, parr_flow_r, parr_flow_t, parr_flow_z,
grad_te_r, grad_te_t, grad_te_z,
grad_ti_r, grad_ti_t, grad_ti_z

Per-cell grid output (SOLPS coupling):

Each fix evaporation instance registers three per-grid-cell accumulators accessible as f_ID[1], f_ID[2], f_ID[3] in SPARTA scripts. Arrays are zeroed once at the start of each active timestep and accumulate contributions from every droplet in the cell across both half-kicks (start_of_step and end_of_step).

Column layout (1-based index in SPARTA scripts):

ColumnSymbolFormulaUnits
f_ID[1]dm_kg ρ (4/3)π (rold3 − rnew3) kg / cell / step
f_ID[2]dn_atoms dm_kg / AM atoms / cell / step
f_ID[3]heat_J Qs · 4π rnew2 · dthalf J / cell / half-step

Symbol definitions:

  • ρ = 534 kg/m3   (liquid Li density)
  • AM = 1.53×10−26 kg   (Li atom mass)
  • rold = droplet radius before the half-step (m)
  • rnew = droplet radius after the half-step (m), ≥ 0
  • Qs = surface heat flux at the droplet position (W/m2)
  • dthalf = dt/2 (half-step duration, s)

Both half-kicks contribute to the same accumulator, so f_ID[1] and f_ID[2] represent the net mass/atom loss over one full timestep dt = 2 × dthalf.

Typical SPARTA script usage (SOLPS coupling):

# time-average dm_kg and dn_atoms over one dump interval (Ndump steps)
fix fml  ave/grid all 1 ${Ndump} ${Ndump} f_fevap[1] f_fevap[2]
dump d_ml grid all ${Ndump} mass_loss.txt id xc yc f_fml[1] f_fml[2]

Post-processing (Python) — Li source rate for SOLPS:

# source_rate [atoms/m^3/s] = mean_dn_atoms_per_step / (dt * cell_vol)
# where mean_dn_atoms_per_step = column f_fml[2] from mass_loss.txt
# and cell_vol is computed from grid geometry (xc/yc spacings or read from grid dump)

Restrictions:

Current evaporation implementation is restricted to 2d geometry for heat-flux interpolation.

Related commands:

compute plasma/fields, fix viscous, dump, variable

Default: none. One heat-flux mode (heatflux/constant or heatflux/file) must be provided.
