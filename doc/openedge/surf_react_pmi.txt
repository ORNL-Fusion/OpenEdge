:line

surf_react pmi command :h3

[Syntax:]

surf_react ID pmi mode reaction_file args ... :pre

ID = user-assigned name for the surface reaction model :ulb,l
pmi = style name of this surface reaction command :l
mode = {constant} or {file} :l
reaction_file = text file defining reaction channels (reflect/sputter/absorb) :l
args = additional arguments depending on mode :l,ule

For {constant} mode:

surf_react ID pmi constant reaction_file.surf RN RE Y Ebind :pre

RN = particle reflection coefficient, probability in \[0,1\] :ulb,l
RE = energy reflection coefficient, fraction in \[0,1\] :l
Y = sputtering yield, atoms/ion (>= 0) :l
Ebind = surface binding energy in eV (>= 0, used for Thompson sputtered energy distribution) :l,ule

For {file} mode:

surf_react ID pmi file reaction_file.surf surface_data.h5 :pre

surface_data.h5 = HDF5 file containing energy- and angle-resolved PMI coefficient tables :ulb,l,ule

[Examples:]

# Constant-mode: quick testing with scalar coefficients
surf_react myPMI pmi constant reactions_DW.surf 0.5 0.8 0.1 8.68 :pre

# File-mode: FTRIDYN BCA tables for O on W
surf_react myPMI pmi file reactions_OW.surf O8_on_W74.h5 :pre

# Pair with diffuse surface collide (velreset=1, so diffuse only thermalizes rot/vib)
surf_collide diffwall diffuse 300.0 1.0
surf_modify all collide diffwall react myPMI :pre

[Description:]

The {surf_react pmi} command implements a general-purpose, data-driven
Plasma-Material Interaction (PMI) surface reaction model for DSMC
simulations. It handles particle-surface interactions by stochastically
deciding among three outcomes for each incident particle: reflection,
sputtering, or absorption. The probabilities and energy/angle distributions
are either specified as constants (for testing and benchmarking) or read
from tabulated HDF5 files (e.g., generated by BCA codes like FTRIDYN or
SDTrimSP).

This replaces hardcoded reflection models (such as those in {surf_react
mpex}) with a modular, table-driven approach that fits the standard SPARTA
surface reaction architecture and enables rigorous PMI modeling for fusion
plasma-surface interaction studies.

[Why this command is needed:]

Fusion edge plasma simulations require accurate modeling of how plasma ions
interact with material surfaces. When a deuterium, tritium, helium, or
impurity ion strikes a plasma-facing component (e.g., tungsten divertor),
three things can happen:

(1) {Reflection}: The ion neutralizes and bounces back into the plasma with
reduced energy. The probability depends on the ion's energy and angle of
incidence. At grazing angles, most particles reflect; at normal incidence,
fewer do. :ulb,l

(2) {Sputtering}: The ion transfers enough energy to knock a wall atom
(e.g., tungsten) out of the surface. This eroded atom enters the plasma as
an impurity and can be ionized, transported, and redeposited elsewhere.
Sputtering yields depend strongly on incident energy and angle. :l

(3) {Absorption}: The ion implants into the surface and is removed from the
simulation. This is the dominant channel at low energies below the
sputtering threshold. :l,ule

The reflection coefficient RN(E,theta), energy reflection coefficient
RE(E,theta), and sputtering yield Y(E,theta) are functions of incident
energy E and angle theta. Binary Collision Approximation (BCA) codes such as
FTRIDYN, SDTrimSP, and TRIM compute these coefficients from first-principles
atomic scattering physics and output them as tabulated datasets. The
{surf_react pmi} command reads these tables and uses bilinear interpolation
to look up the correct coefficients for each particle-surface collision.

Previous approaches used hardcoded energy/angle ranges, had CDF
normalization issues, and mixed concerns between lookup, decision, and
sampling. The {surf_react pmi} design cleanly separates these steps and
integrates with SPARTA's existing surface collision/reaction architecture,
including automatic compatibility with diagnostics like {compute iead} and
{compute react/surf}.

[Reaction file format:]

The reaction file uses the same two-line-per-reaction text format as
"surf_react prob"_../surf_react.html, but with PMI-specific reaction types.
Lines beginning with # are comments. Blank lines are skipped.

# Example: D+ on W surface reactions
#
# Line 1: reactant --> product (species formula)
# Line 2: type style coeff
#
D+ --> D
R Simple 1.0 :pre

D+ --> W
S Simple 1.0 :pre

D+ --> NULL
A Simple 1.0 :pre

Three reaction types are recognized:

{R} (Reflect): The incident particle neutralizes and is re-emitted as the
product species. The incident particle's species is changed to the product
(e.g., D+ becomes D). A new velocity is assigned using cosine-law direction
sampling into the outward hemisphere, with speed set by RE*E_incident. The
original particle pointer (ip) is updated; no secondary particle (jp) is
created. :ulb,l

{S} (Sputter): The incident particle is absorbed (ip=NULL). A new secondary
particle (jp) is created as the product species (e.g., a wall atom W). The
sputtered particle's energy is sampled from a Thompson distribution
F(E) ~ E/(E+Eb)^3 with Eb = E_bind/2 and Emax = E_incident. Direction
is cosine-law into the outward hemisphere. If tabulated CDFs are present
in the HDF5 file, those are used instead of the Thompson/cosine fallback. :l

{A} (Absorb): The incident particle sticks to the surface and is removed
from the simulation (ip=NULL, jp=NULL). :l,ule

The coefficient on line 2 (1.0 in examples) is a placeholder; actual
probabilities come from the table lookup or constant-mode values. Each
incident species should have at most one R, one S, and one A reaction
defined. The code maps species to their reaction roles at initialization.

[Algorithm:]

For each particle-surface collision, the {react()} method executes:

(1) Compute incident kinetic energy E_eV = 0.5*m*v^2 (in eV) and
incidence angle theta (degrees from surface normal, 0=normal, 90=grazing)
from the particle velocity and surface outward normal vector. :ulb,l

(2) Look up RN(E,theta), RE(E,theta), Y(E,theta) via bilinear
interpolation on the energy x angle grid (file mode) or use the scalar
constants (constant mode). Values are clamped to physical bounds. :l

(3) If RN+Y > 1, renormalize both by dividing by (RN+Y) so that the
total reaction probability does not exceed unity. The absorption
probability is then P_absorb = 1 - RN - Y. :l

(4) Draw a uniform random number u in \[0,1\]: :l

u < RN: REFLECT :ulb,l
u < RN + Y: SPUTTER :l
otherwise: ABSORB :l,ule

(5) Set {velreset=1} to signal that this reaction owns the outgoing
particle velocities. The paired {surf_collide diffuse} will still
thermalize rotational/vibrational energies but will not re-randomize
translational velocity. :l,ule

[HDF5 file layout (file mode):]

The HDF5 surface data file must contain the following datasets:

{E}\[nE\] = energy axis in eV, ascending, 1-D array :ulb,l
{A}\[nA\] = angle axis in degrees (0=normal incidence), ascending, 1-D array :l
{RN}\[nE,nA\] = particle reflection coefficient, values in \[0,1\] :l
{RE}\[nE,nA\] = energy reflection coefficient, values in \[0,1\] :l
{spyld}\[nE,nA\] = sputtering yield in atoms/ion, values >= 0 :l
{E_bind} = scalar: surface binding energy in eV :l,ule

Optional datasets for tabulated output distributions (CDFs):

{edist_R}\[nE,nA,nb\] = reflected energy CDF :ulb,l
{adist_R}\[nE,nA,nb\] = reflected angle CDF :l
{edist_Y}\[nE,nA,nb\] = sputtered energy CDF :l
{adist_Y}\[nE,nA,nb\] = sputtered angle CDF :l,ule

When CDFs are present, inverse-CDF sampling replaces the default
Thompson energy distribution and cosine-law direction sampling. This
enables use of BCA-computed output distributions for higher fidelity.

The nE and nA axes must each have at least 2 points. The code uses
bilinear interpolation with clamping at grid boundaries (no
extrapolation).

[Constant mode:]

Constant mode is provided for testing, benchmarking, and simple cases
where energy/angle dependence is not important. All four scalar
parameters (RN, RE, Y, Ebind) are applied uniformly regardless of
incident energy or angle. For example, setting RN=0.5, Y=0.1 with
Ebind=8.68 eV reproduces a standard impurity transport benchmark on
tungsten surfaces.

[Erosion/deposition tracking:]

The command provides several hooks for erosion and deposition analysis:

{Per-reaction tallies}: The inherited {tally_single\[i\]} array counts
each reaction type (reflect, sputter, absorb) per timestep. These are
accessible via {compute_vector} with indices 2..2+nlist-1 for
single-step counts and 2+nlist..2+2*nlist-1 for cumulative totals.
This allows tracking gross erosion (sputter count), gross deposition
(absorb count), and reflection count per step. :ulb,l

{last_outcome member}: An integer (1=reflect, 2=sputter, 3=absorb)
recording the most recent reaction outcome. This provides a
lightweight hook for companion compute styles. :l

{compute iead compatibility}: Since {surf_react pmi} uses the standard
{react()} interface, the original particle state ({iorig}) is
automatically captured by {SurfCollideDiffuse::collide()} and passed to
surface tally callbacks. The {compute iead} style will automatically
histogram all surface impacts without any special handling. :l

{compute react/surf}: The standard {compute react/surf} command works
with {surf_react pmi} to provide per-surface-element reaction counts
and rates. :l,ule

[Comparison with other surface reaction styles:]

{surf_react prob}: Uses probability coefficients directly from the
reaction file. No energy/angle dependence. Suitable for simple
chemistry (dissociation, exchange, recombination) but not for
physics-based PMI modeling. :ulb,l

{surf_react mpex}: Uses hardcoded tanh-based angle-dependent reflection
coefficients specific to the MPEX experiment. Does not support
sputtering. Not generalizable to other projectile/target combinations. :l

{surf_react global}: Simple probability-based delete/create model with
no species specificity or energy dependence. :l

{surf_react pmi}: General-purpose, data-driven model supporting any
projectile/target combination via HDF5 tables. Handles reflection,
sputtering, and absorption with proper energy and angle dependence.
Includes Thompson energy sampling for sputtered particles and
cosine-law direction sampling. Supports optional tabulated CDF
distributions for maximum fidelity. :l,ule

[Output info:]

This surface reaction style is compatible with the following output
commands:

"compute react/surf"_../compute_react_surf.html tallies the number of
reactions of each type on each surface element :ulb,l

Global vector with {size_vector = 2 + 2*nlist}: :l

index 0 = total reactions this step (all types) :l
index 1 = cumulative total reactions :l
indices 2..2+nlist-1 = per-reaction-type counts this step :l
indices 2+nlist..2+2*nlist-1 = cumulative per-reaction-type counts :l,ule

[Restrictions:]

This command requires SPARTA to be built with HDF5 support (file mode).
The {find_package(HDF5 REQUIRED COMPONENTS CXX)} directive in CMakeLists.txt
handles this automatically.

The reaction file must define at most one R, one S, and one A reaction
per incident species. Multiple incident species are supported (e.g.,
D+ and C+ can each have their own reflect/sputter/absorb channels).

In file mode, the HDF5 file must contain at minimum: E, A, RN, RE,
spyld datasets. The E_bind scalar is optional (defaults to 0).
